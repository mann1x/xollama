# llama/runtime-pin-windows-mlx.txt
#
# The MLX runtime a Windows install takes, pinned as a published artifact and
# never built here. From v0.40.9 it is upstream's own ollama-windows-amd64-mlx.zip,
# republished byte for byte by the fork; the fork's old -reldir build is retired
# (see LAYOUT). It carries two directories under lib/ollama:
#   mlx_cuda_v13\  mlx, mlxc, ollama_xgrammar, libopenblas and the 8 cuDNN 9
#                  DLLs. mlx.dll loads cuDNN from its own folder, so no cuDNN
#                  need be installed on the machine.
#   cuda_v13\      cufft64_12, cusolver64_12, cusparse64_12 -- the CUDA
#                  libraries MLX needs that GGML does not. The rest (cublas64_13,
#                  cublasLt64_13, cudart64_13, nvrtc64_130_0, nvrtc-builtins64_130,
#                  nvJitLink_130_0) mlx.dll loads from ..\cuda_v13, the GGML
#                  CUDA-13 backend the full installer lays in lib\ollama\cuda_v13.
# app/xollama-mlx.iss unpacks BOTH and merges the cuda_v13 DLLs beside the GGML
# backend (never replacing it).
#
# LAYOUT (upstream #17956, from v0.40.9): upstream deduplicated the CUDA
# libraries MLX shares with GGML and, on Windows, CACHE FORCEs
# MLX_CUDA_BIN_DIR=..\cuda_v13 and MLX_CUDNN_BIN_DIR=. Upstream's own v0.40.9
# mlx.dll embeds "..\cuda_v13" and ships the cuDNN DLLs beside itself, which is
# exactly what the fork's -reldir build existed to provide -- so -reldir is
# retired and the plain zip is pinned. The fork's only=mlx-windows job (which
# built -reldir) is retired with it (owner, 2026-10-23).
# Verified on eleven2go (no cuDNN installed), 2026-10-23, against this sha256:
# mlx.dll has NO hardcoded NVIDIA\CUDNN path (the v0.40.0 panic string, gone),
# embeds the relative ..\cuda_v13, and the 8 cuDNN DLLs ship in mlx_cuda_v13 --
# so the no-cuDNN failure mode is structurally eliminated. The end-to-end MLX
# generation check (G9) runs at rc once the v0.40.9 MLX xollama binary exists.
#
# It is NOT inside xOllamaSetup.exe: the installer plus this archive would be
# about 2.5 GiB, over GitHub's 2 GiB release-asset cap (upstream's own
# OllamaSetup.exe leaves MLX out too). The installer DOWNLOADS it instead
# (app/xollama-mlx.iss, owner 2026-10-07), from repo/tag/asset below, and
# refuses any bytes whose sha256 is not this one. The release workflow hands
# the four values to the installer build (PKG_MLX_*).
#
#   repo          GitHub repository that publishes the archive (the fork)
#   tag           its release carrying the asset
#   asset         archive name (lib/ollama/mlx_cuda_v13 + lib/ollama/cuda_v13)
#   sha256        of the asset, checked by the installer before unpacking
#   upstream      ollama/ollama release the bytes were cut from
#   mlx, mlx_c    upstream's MLX_VERSION and MLX_C_VERSION at that release;
#                 they must equal this tree's (the plan job refuses otherwise)
#
# Moves with llama/runtime-pin-darwin.txt and the two Linux runtime pins on
# every fork sync.
