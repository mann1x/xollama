# llm/engine/pin.txt
#
# Pinned opencoti-llamafile ARTIFACT, bundled into the xollama runtime payload
# at BUILD time and shipped inside the installation package beside
# llama-server. xollama NEVER downloads an engine at runtime: a model load must
# not be able to stall on a 700 MB fetch, and a release package must not depend
# on the network to work.
#
# Read by two consumers, which is why the format is boring:
#   - cmake/opencoti-engine.cmake  fetches and verifies it into the payload
#   - llm/engine/pin.go            embeds it, for provenance and for tests that
#                                  keep this file honest
#
# Source of record is Hugging Face only (ManniX-ITA/opencoti-llamafile). The
# artifacts exceed GitHub's release-asset cap and live on HF as LFS blobs.
# URL shape: https://huggingface.co/<repo>/resolve/<rev>/<hf-path>
#
# ---------------------------------------------------------------------------
# FORMAT
#
# Comments (#) and blank lines are ignored. Two kinds of line:
#
#   Directives (key + value):
#     repo <hf-owner/name>    HF repo hosting the assets
#     rev  <git-revision>     HF revision (branch/tag/commit)
#     tag  <release-tag>      human release tag, provenance only
#
#   Asset rows (4 whitespace-separated fields):
#     <kind> <arch> <hf-path> <sha256>
#       kind   bin (the engine) -- dso rows are opencoti's side-load story and
#              are deliberately NOT carried here: the x86_64 and aarch64
#              artifacts embed their own GPU payloads and self-extract.
#       arch   x86_64 | aarch64 | win-x86_64 | win-x86_64-gpu | universal
#       sha256 verified by CMake at fetch time; a mismatch fails the build
#              rather than shipping an unknown binary.
#
# To move to a new cut: bump rev/tag and replace the sha256 of every row, in
# one commit. The digests below were verified against the published artifacts.
# ---------------------------------------------------------------------------
